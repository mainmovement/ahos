# 5. TOKEN IDENTITY IS A CRITICAL SAFETY BOUNDARY

One of the most important requirements in all of AHOS is:

> **A token's identity must be correct before its intelligence can be trusted.**

For every token, AHOS must strive to establish:

```text
Name
Symbol
Chain
Contract Address
Pool / Pair Identity
DEX
Quote Asset
Launch / Pair Creation Time
Source Provenance
Identity Confidence
```

The **contract address must never be guessed**.

A symbol alone is not sufficient.

A token name alone is not sufficient.

A search result alone is not sufficient.

If multiple assets share the same symbol/name:

```text
IDENTITY = AMBIGUOUS
```

If authoritative identity cannot be established:

```text
DECISION = MONITOR_ONLY / UNRESOLVED
```

The system must fail closed rather than silently attaching intelligence to the wrong contract.

This requirement has extremely high priority because an incorrect contract address can invalidate:

* security analysis,
* liquidity analysis,
* holder analysis,
* whale analysis,
* price analysis,
* paper trades,
* historical results,
* and every downstream conclusion.

Potential assets before meaningful public market activity.

### B. NEWLY LAUNCHED

Early-stage assets with emerging evidence.

> **Is this sufficiently dangerous, fraudulent, manipulated, illiquid, or unverifiable that we should avoid it?**

Opportunity discovery and danger discovery are equally important.

5. کم‌خطرترین راه‌حل عمومی را انتخاب کن؛
6. اصلاح کن؛
7. تمام تست‌های مرتبط را دوباره اجرا کن؛
8. نقدها را دوباره اجرا کن؛
9. مطمئن شو اصلاح، defect جدید ایجاد نکرده؛
10. سپس commit کن.

اگر راه‌حل اول ضعیف بود، آن را حفظ نکن فقط چون قبلاً تولید شده است.

```text
Previous Output Is Not Sacred.
Quality Has Priority Over Attachment.
```

# 10. Git Commit / Push / Merge Protocol

هر تغییر معنادار باید مرتب و قابل‌ردیابی ثبت شود.

## Commit باید:

* کوچک و منطقی باشد؛
* یک هدف روشن داشته باشد؛
* پیام دقیق داشته باشد؛
* تست‌های مربوط را مشخص کند؛
* از commitهای مبهم مانند `update`, `fix`, `changes` پرهیز کند؛
* فایل‌های بی‌ربط را وارد نکند؛
* secret یا credential نداشته باشد؛
* artifact موقت و cache را وارد نکند.

فرمت پیشنهادی:

```text
<area>: <precise change>

Why:
...

Tests:
...

Verification:
...

Risk:
...
```

## قبل از Push

بررسی کن:

* working tree؛
* diff؛
* staged files؛
* secrets؛
* `.pyc`؛
* cache؛
* generated junk؛
* accidental reports؛
* branch؛
* remote؛
* commit history؛
* test status.

## Push

اگر authentication معتبر و دسترسی موجود است:

1. branch فعلی را push کن؛
2. remote HEAD را بررسی کن؛
3. مطمئن شو commit واقعاً روی GitHub قرار گرفته؛
4. در صورت نیاز PR بساز؛
5. checks را بررسی کن؛
6. فقط در صورت معتبر بودن merge کن.

## Merge

Merge فقط زمانی مجاز است که:

* تغییرات واقعاً بررسی شده باشند؛
* تست‌های لازم پاس شده باشند؛
* conflict وجود نداشته باشد؛
* Lane A نقض نشده باشد؛
* security review انجام شده باشد؛
* documentation به‌روز باشد؛
* تغییر در وضعیت مناسب governance باشد؛
* merge باعث جعل readiness نشود.

از این کارها ممنوعی:

```text
force push بدون ضرورت واقعی
reset مخرب
rebase مخرب
squash کردن بدون دلیل
حذف commitهای معتبر
حذف evidence
پنهان‌کردن شکست تست
تغییر دادن گزارش برای سبز نشان‌دادن وضعیت
```

اگر push به‌دلیل token یا permission ممکن نبود:

* تغییرات را از بین نبر؛
* commitهای محلی را حفظ کن؛
* دقیقاً `PUSH_BLOCKED_EXTERNAL` ثبت کن؛
* به توسعه dependency-safe ادامه بده؛
* دوباره در زمان مناسب تلاش کن؛
* هرگز به‌خاطر push blocker، repository را خراب نکن.

در ربات یک ایجنت مسئول حسابداری هست در تمام بخش‌ها و یک ایجنت مخصوص دریافت رمز ها پسوردها یوزر نیم ها آدرس های مختلف کیف پول با هر اسم و مشخصاتی هست برای افتتاح حساب یا انتقال دادن از حسابی به حساب دیگری یا نقد کردن یا تبدیل کردن که از واحد کریپتو اکه نیاز بود بده به واحد نفت یا از واحد طلا بده به بپرس یا واریز به حساب شخصیم چه نقد کنم حتما از agi و aci استفاده هم بشه . دانشگاه هم آموزشش بده کلا تمام ایجنت ها مرتب باید آموزش ببینن بهینه قوی سریع که خودشون رو ابدیت کنن
خیلی ها دارن از فرا هوش های به روز مثل astra ai و شبیه اون استفاده میکنن و پروژه ها . یا اسکیلها و یا مواردی ساختن که خیلی بالاتر از ما هستن کلاد ایجنت هایی که به کلاد میدیم ایجنت ها ی ربات دانشگاه باید اینها رو پیدا کنن و استفاده کنن ازشون که عقب نمونبم
در ربات یک گروه ایجنت هستن فقط کارشون خبرگزاری هست و میرن در هر زمینه و هر سبکی هر تمام خبرگزاری ها و سایت ها که مرتبط با لاین های مختلف ربات هستن رو پیدا می‌کنه و در اختیار لاین های مختلف ربات میزاره چون در تصمیم گیریشون و پیش خرید کردنشون و اینکه باعث بشه زودتر بخرن و به موقع بخرن و به موقع بفروشن واسه اینکه سود بیشتر ببرن پس اخبار مهمه هم برای دانشگاه که ابزار های جدید و مطالعات جدید رو انجام بده هم خرید در لاین طلا لاین بورس‌ها لاین نفت ها لاین توکن ها لاین کریپتو ....و اخبار در حتی فیوچرز اثر داره علم روز اسکیلها فرا هوش ها پروژه های گیت هاپو اینکه در این ایجنت ها agi و aci عملکرد عالی باید داشته باشه
یک گروه ایجنت هم باید بتونن ربات تلگرام رو جوری راه بندازن که راحت بتونم باهاش چت کنم و هر خواسته ای رو باهاش مطرح کنم و همین فرا هوش در داشبورد هم باشه در لوکال لب تاب و حتما تاکید میکنم agi و aci در این زمینه فعال باشن و خیلی از هوش مصنوعی گراک بات هم الگو بگیره
پیشنهاد سایت کن که درخت و ریشه و از اینها هست رو هم اکه مناسب نبود می‌تونه زیباترین الگو هارو جایگزین کنه برای داشبورد در لبتاب و agi و aci رو هم در داشبورد و طراحی در نظر بگیره
