## What the /api/chat DB-failure contract actually is (module-level)

A real chat message reaches the AI provider *before* the DB write, so no
end-to-end leg can exercise the DB-failure path without a paid call. The
empty-message leg above is the safe substitute.

The route handler (app/api/chat/route.ts) is untouched by M10 - see the git
diff - so its behaviour is the pre-existing contract, recorded here rather
than claimed.

```
PROBE_RESULT=db_error
TRANSIENT_CLASSIFIED=false
ERROR_NAME=Error
MESSAGE_HEAD=Failed query: select "id", "role", "content", "intent", "evidence", "created_at" from "ahos_chat_messages" limit $1
CAUSE_TAIL=connect ECONNREFUSED 127.0.0.1:5432
```

**Correction to the v1 receipt.** The retry-then-500 branch in the route is
*not reachable from a store failure*: chat.ts persistChat() wraps both
inserts in a try/catch that swallows the error (DB optional when
DATABASE_URL missing), so a failing store never throws out of
conversationGateway(). What the contract actually guarantees on a dead
store:

- GET /api/command -> 200 with a fail-closed snapshot
  (snapshot.ts:111-118 catches every error and returns running: false
  plus the redacted last error). Leg B above is that path, observed end
  to end against an unreachable store.
- POST /api/chat -> 200 with a normal reply; the failed persistence is
  swallowed and never surfaces to the caller. The route's 500-with-hint
  branch fires on *provider* failures, not store failures.

Both are honest degradation, and M10 changes neither branch.

## Addendum: the defect this smoke caught (2026-10-07)

Hand-written after the run, appended rather than edited into the output above.

The first run of this harness produced Leg A's `lastError` as
`commandSnapshot failed: pgliteDataDir is not defined` — a live
`ReferenceError` on the gateway's PGlite path. `db/index.ts` re-exported
`pgliteDataDir` (`export { ... } from "./pglite_url.mjs"`) without importing
it as a local value binding, so `getPgliteClient()` referenced an undeclared
name at runtime. TypeScript did not catch it: the re-export makes the name
visible to the type system while leaving it unbound at runtime.

Had the owner flipped `.env` before this smoke, the gateway would have booted
and then failed closed on every request. The fix is a value import in
`db/index.ts`, and `scripts/pglite_backend_selftest.ts` now has a regression
test that opens a throwaway dataDir through `db.$client` and asserts
`PG_VERSION` appears — the failure only reproduces on the real lazy-client
path. Selftest is 17/17.

This is the case for the harness: the bug was invisible to `tsc` and to every
unit test that imported the module without exercising the lazy singleton.
