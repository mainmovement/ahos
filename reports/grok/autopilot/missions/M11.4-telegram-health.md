# M11.4: telegram component health = stable process, not "pid alive at spawn"

## Evidence (box)
Without TELEGRAM_BOT_TOKEN, `launcher start` printed `ربات تلگرام: ✓` and overall ONLINE; 20 s later
`launcher status` said `telegram UNAVAILABLE recorded pid ... is not a live AHOS process` (run_bot.py
preflight exits: "❌ پیش‌نیازها کامل نیست"). `components.probe_process` returns HEALTHY as soon as the pid is alive.

## Required change (launcher/components.py, launcher/orchestrator.py)
- Health for telegram: alive for >= N seconds (e.g. 8 s, configurable in HEALTH_WAIT) AND, if available, an
  explicit readiness signal (e.g. a heartbeat/ready line run_bot.py already logs, or a small ready file under
  get_data_dir()/launcher). Never read or print the token.
- If the bot exits during the window, report UNAVAILABLE with the last 3 lines of logs/launcher/telegram.log
  (redacted via the existing secret patterns) and the Persian action "TELEGRAM_BOT_TOKEN".

## Acceptance
- Unit test: a fake child that exits after 1 s -> start reports telegram UNAVAILABLE, overall DEGRADED.
- Box: start without token -> DEGRADED immediately (not ONLINE).
