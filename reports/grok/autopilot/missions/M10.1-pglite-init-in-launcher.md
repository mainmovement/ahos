# M10.1: initialise the PGlite store from the launcher (no manual restore step)

## Evidence (box)
With `DATABASE_URL=pglite:<dir>` and an empty dir, the gateway starts and /api/command returns
`relation "ahos_system_state" does not exist` until someone runs
`node --experimental-strip-types scripts/pglite_restore.ts --dataDir <dir>` (applies drizzle/0000, 33 statements).
launcher `db_backend` probe only checks that the dir is non-empty.
## Required change
launcher/components.py + orchestrator.py: when the backend is pglite and the dir has no PG_VERSION, run the
existing restore tool in schema-only mode (no --dump) once, before the gateway (CREATE_NO_WINDOW / POSIX ok),
record the result in the status report. Probe = PG_VERSION exists AND table ahos_system_state exists (via the
same tool in a read-only check mode, add `--check` to scripts/pglite_restore.ts).
Never run db:migrate/db:push against Postgres (STATE B rule).
## Acceptance
Box: fresh dir -> `python -m launcher start` -> /api/command 200 with lastCycleStatus UNKNOWN (no relation error).
Unit tests for the decision logic with a fake runner.
