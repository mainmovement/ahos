# M11.3: gateway process identity (idempotent second start, clean stop)

## Evidence
- Box (Linux, branch grok-box-debug): start -> start: second start reports the launcher's OWN gateway as
  `foreign_busy` ("port 3000 occupied by another program") and overall DEGRADED.
- Laptop receipt reports/launcher/smoke_idempotent_20261003T164942Z.json (untracked): verdict
  `second_start_was_idempotent_replay: False`, `restart_after_stop_worked: False`, `passed: False`.

## Root cause
`AhosOrchestrator.marker("gateway")` = `<root>\node_modules`, but the recorded pid is the spawned wrapper:
Windows `cmd /c "npm run start --silent"`, POSIX `npm run start --silent`. Neither command line contains
`node_modules`, so `pk.pid_is_ours(gateway_pid, marker)` is always False (same class of bug as the Phase 11
engine `-m` marker). Consequences: no idempotent replay for the gateway, `_classify` falls to the port check ->
foreign_busy; `_recorded_gateway()` (box commit b636b01) can never confirm the gateway, so the recorded
fallback port is not reused across processes on a real host.

## Required change (launcher/components.py, launcher/orchestrator.py, launcher/processkit.py)
Pick ONE and document it in docs/ONE_CLICK.md:
(a) spawn the gateway as `[<node>, <root>/node_modules/next/dist/bin/next, start|dev, --hostname, 127.0.0.1]`
    (node from PATH / `where node`), so the recorded pid IS the server and its argv carries the marker; keep
    package.json scripts as the human entry point; or
(b) keep npm, and make gateway identity = recorded pid alive AND a descendant (processkit.descendant_of +
    process_snapshot / fill_cmdlines on Windows, /proc on POSIX) whose cmdline contains the marker.
Do not loosen the marker to a generic `npm run start` substring (other projects match it).

## Acceptance
- Unit: TestProcessMarkers-style test that the gateway marker is a substring of the argv actually spawned
  (or of the descendant's cmdline under (b)).
- Box-reproducible: `python -m launcher start; start; status; stop; status` -> second start
  `gateway: HEALTHY already running (idempotent)` at the same pid, status ONLINE/DEGRADED only for telegram,
  stop leaves no listener on the gateway port.
- Windows owner receipt: `python launcher/smoke.py idempotent` verdict passed=True.

PAPER_ONLY; no .env edits; never kill a process that is not proven ours; no push.
